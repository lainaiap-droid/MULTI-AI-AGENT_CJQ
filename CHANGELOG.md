# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версионирование — [SemVer](https://semver.org/lang/ru/).

## [1.5.0] — 2026-11-13

Добавлен слой evals — автоматическая оценка качества артефактов агентов. Архитектура остаётся «1 + 3»: evals не агент, а отдельный инструмент.

### Добавлено

- Каталог `.opencode/evals/` на чистом Node ESM без зависимостей: парсер артефактов, модель, проверки, отчёты.
- CLI `run-evals.mjs`: `--list`, `--case`, `--stage`, `--verbose`, `--md`, `--json`, `--baseline`, `--update-baseline`, `--judge`, `--judge-ingest`, `--selftest`.
- Детерминированные проверки: frontmatter, обязательные секции, Gate Self-Check, шаблонные заглушки, формат и уникальность ID, трассировка REQ → BR/AC → TASK → TC, согласованность Coverage, арифметика Coverage Map, секреты, PII, абсолютные пути, маркеры запуска, общий `run_id`.
- LLM-judge без вызова модели из CLI: промпт по рубрике кейса, приём оценок JSON через `EVAL_JUDGE_CMD` или вручную, валидация баллов и порог PASS.
- `selftest.mjs` — мутационные тесты: каждая проверка обязана поймать внесённый дефект.
- Публичный кейс `SYN-SORT-001` (10 REQ, 4 TASK, 9 TC, coverage 9/1/0) с синтетическим источником.
- Skill `evals` — процедура запуска и интерпретации результатов.
- `.opencode/evals/README.md` — формат кейса, команды, judge-протокол, CI.

### Изменено

- `qa-lead`: доступ на чтение `.opencode/evals/**`, секция Evals, исключение для skill `evals` в запрете на загрузку skills.
- `.gitignore`: исключены `evals/cases/private/` и `**/_judge/`.

### Известные ограничения

- CLI не вызывает модель сам: для автоматической оценки нужен `EVAL_JUDGE_CMD` или ручной ответ оценщика.
- Приватный набор кейсов в репозиторий не входит и на чистом клоне недоступен.
- Eval-вердикт не заменяет Quality Gate и не отменяет решение `qa-lead`.

## [1.4.0] — 2026-11-12

Первая версия мультиагентной архитектуры «1 + 3». Пилотный запуск по полному циклу Confluence → Jira → Qase пройден.

### Добавлено

- `qa-lead` — primary-агент: оркестратор, владелец внешних записей и итогового отчёта. Единственный, кто общается с пользователем и вызывает Confluence, Jira, Qase.
- Дочерние агенты без внешних инструментов: `requirement-reviewer`, `task-designer`, `test-designer`. Передача результата — только через файлы артефактов.
- Плагин `.opencode/plugins/confluence/index.ts` — Confluence REST API v2, только чтение. Четыре инструмента `confluence_*`, поле `contentStatus` в метаданных страницы.
- Резервный MCP-сервер `.opencode/mcp/qa-tools.mjs` (Confluence + Qase); используется только при недоступности штатного пути и с подтверждения пользователя.
- Каталог артефактов `.opencode/artifacts/` с шаблонами `_templates/` и описанием `README.md`.
- `references/integrations.md` — фактические контракты инструментов, схема хранения секретов, правила доступа.
- `.gitignore` — политика исключений: секреты, артефакты запусков, локальный конфиг, IDE, черновики.

### Изменено

- `.opencode/opencode.jsonc`: путь к `qa-tools.mjs` сделан относительным, возвращён `$schema`, токен Qase подаётся через `{file:~/.secrets/qase-token}`.
- `cloudId` Jira, хост Atlassian и accountId убраны из репозитория. `cloudId` получается за запуск через `jira_getAccessibleAtlassianResources`.
- Старые tools `.opencode/tools/*.ts` перенесены в `.opencode/legacy-v1/`: в OpenCode V2 они не регистрируются.

### Исправления

- Убраны ссылки на черновики `TEMP/confluence.ts` из документации и комментариев кода.
- Qase-инструменты ограничены allowlist; изменяющие операции (`edit`, `delete`, `run`) запрещены.
