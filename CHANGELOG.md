## [1.4.2] — 2026-11-14

Патч линии 1.4.x: первый полностью успешный прогон eval-стадии `full-cycle`. Контракты агентов не меняются.

### Добавлено

- `.opencode/evals/eval_runner.py` — раннер eval-стадий: изоляция `run_id`, запуск `qa-lead` через `Popen` с watchdog, сбор артефактов для judge, расчёт метрик и Quality Gate, отчёты `eval_results.json` и `eval_report.md`.
- `.opencode/evals/evaluator.py` — LLM-as-a-Judge: задание передаётся файлом, потому что `opencode run` обрезает сообщение на первом переводе строки.
- `.opencode/evals/source_refs.py` — разрешение ссылок на источники: `page_ref` из датасета превращается в фактический `page_id` через переменную окружения или `.opencode/local.jsonc`.
- `.opencode/agents/eval-judge.md` — отдельный агент-судья без инструментов.

### Изменено

- `.opencode/agents/qa-lead.md`: `steps` поднят с 60 до 200 — прогоны упирались в лимит шагов, а не в таймаут; действия Qase приведены к виду `<server>_<tool>`, иначе широкое `qase*: deny` закрывало весь сервер; резервный `qa-tools` закрыт явно, поскольку в non-interactive режиме `ask` подтвердить некому.
- `.opencode/evals/dataset/golden_dataset.json`: `page_id` заменён на `page_ref`, реальный идентификатор страницы в git не попадает; критерии 4 и 5 переписаны — убрана ложная посылка об отсутствии Unconfirmed Fragments и привязка к RR-ID, которые меняют смысл между прогонами.
- `.gitignore`: исключены результаты eval-прогонов, `__pycache__/` и `*.pyc`.

### Примечание

- Результат прогона `RUN-20261114-173537`: Quality Gate PASS, 8/8 Expected Properties, 0/5 нарушений Forbidden Behavior, 0 ошибок, 93 шага из 200.
- Слой evals по-прежнему не переносится в `main`: он остаётся в ветке `feature/evals-v2` линии 1.4.

- `MULTIAGENT_PLAN.md`: отмечены выполненные пункты этапов 5–6, добавлены фактические результаты пилота — 12 задач `UP-1`…`UP-12`, 37 кейсов Qase, покрытие 29/4/1.

## [1.4.0] — 2026-11-12

Первая версия мультиагентной архитектуры «1 + 3». Пилотный запуск по полному циклу Confluence → Jira → Qase пройден.

### Добавлено

- `qa-lead` — primary-агент: оркестратор, владелец внешних записей и итогового отчёта. Единственный, кто общается с пользователем и вызывает Confluence, Jira, Qase.
- Дочерние агенты без внешних инструментов: `requirement-reviewer`, `task-designer`, `test-designer`. Передача результата — только через файлы артефактов.
- Плагин `.opencode/plugins/confluence/index.ts` — Confluence REST API v2, только чтение. Четыре инструмента `confluence_*`, поле `contentStatus` в метаданных страницы.
- Резервный MCP-сервер `.opencode/mcp/qa-tools.mjs` (Confluence + Qase); используется только при недоступности штатного пути и с подтверждения пользователя.
- Каталог артефактов `.opencode/artifacts/` с шаблонами `_templates/` и описанием `README.md`.
- `references/integrations.md` — фактические контракты инструментов, схема хранения секретов, правила доступа.
- `.gitignore` — политика исключений: секреты, артефакты запусков, локальный конфиг, IDE, черновики.

### Изменено

- `.opencode/opencode.jsonc`: путь к `qa-tools.mjs` сделан относительным, возвращён `$schema`, токен Qase подаётся через `{file:~/.secrets/qase-token}`.
- `cloudId` Jira, хост Atlassian и accountId убраны из репозитория. `cloudId` получается за запуск через `jira_getAccessibleAtlassianResources`.
- Старые tools `.opencode/tools/*.ts` перенесены в `.opencode/legacy-v1/`: в OpenCode V2 они не регистрируются.

### Исправления

- Убраны ссылки на черновики `TEMP/confluence.ts` из документации и комментариев кода.
- Qase-инструменты ограничены allowlist; изменяющие операции (`edit`, `delete`, `run`) запрещены.

- Requirement Review: 34 REQ, 15 BR, 11 AC, Gate PASS.

- Test Model: 46 сценариев; в Qase создано 37 кейсов (suite «Доработка №3. Версионность вложений»).

### Известные ограничения

- `.opencode/AGENTS.md` сохраняет формулировки, унаследованные от единоагентной версии; фактическая оркестрация описана в `agents/qa-lead.md`.
